# 单版本静态场景展厅简化设计

**日期：** 2026-08-12  
**状态：** 已实现并完成六场景视觉复核
**目标仓库：** `Shuaijun-LIU/demo`

## 1. 目标

将现有 Line 1 / Line 2 双版本、多面板、可播放的多机械臂页面，收敛为一个明亮、克制、只用于检查场景空间构型的静态 3D 展厅。

最终页面保留六个 Franka Panda 多机械臂场景，但不再显示 Line 1 或 Line 2 概念。用户只能切换场景、拖动视角和缩放；机械臂、物体和设备不会自行运动。

## 2. 已确认的产品原则

1. Line 2 从前端产品中完整移除，不保留选择入口、运行路径或独立资产层。
2. 原 Line 1 成为唯一场景版本，但页面中不出现 Line 1 名称。
3. 页面不是控制台、播放器或任务执行器，只是静态场景展示。
4. 页面和三维环境以白、灰白、浅灰和石墨灰为主，不使用夜间模式、霓虹青蓝、发光边框或高饱和渐变。
5. 保留少量低饱和工业色，用于区分物料、设备状态和机械臂角色，但不作为大面积主色。
6. 六个场景必须保持可切换、可旋转查看和可缩放。
7. 初始视角下以及允许的轨道视角范围内，不应出现重复模型、明显相交、桌面穿透或物体悬空。

## 3. 信息架构

页面只保留三层信息：

1. 顶部标题：`多机械臂场景展示`，附一行简短说明。
2. 六场景选择器：显示编号与短标题，当前场景使用低对比度灰色选中态。
3. 主展示区：大幅 3D 视窗，左上角显示当前场景名称和机械臂数量，右下角显示“拖动旋转 / 滚轮缩放”。

下列现有模块全部移除：

- Line 1 / Line 2 选择器；
- WebGL、机械臂数量和版本状态胶囊；
- 场景运行状态与加载过程文案；
- 机械臂角色图例；
- 连续任务路径；
- 当前检查、物料流、分流位和可见设备侧栏；
- 播放、暂停和复位按钮；
- 底部机械臂任务泳道；
- 运动、故障恢复、任务闭环等运行态表达。

## 4. 视觉设计

### 4.1 页面

- 页面背景：暖灰白或中性灰白。
- 面板背景：纯白或接近白色。
- 边框：浅灰，无发光和高对比描边。
- 主文字：石墨黑；次级文字：中灰。
- 选中态：浅灰底、深灰文字、细石墨色下划线或描边。
- 阴影：只使用非常轻的自然阴影表达层级。

### 4.2 三维视窗

- 背景和雾：浅灰白，不使用深蓝或黑色。
- 地面：哑光浅灰，网格线改为低对比度灰色。
- 灯光：模拟明亮室内摄影棚，使用中性白主光和柔和补光。
- 自定义工位：桌面、基座、支架以白、浅灰、金属灰为主。
- 功能色：使用低饱和蓝灰、鼠尾草绿、赭黄和砖红，仅用于少量对象识别。
- Franka Panda 保留其原始白、黑、金属配色。

## 5. 静态渲染行为

`SceneViewport` 只负责加载场景和相机交互：

- MuJoCo 永久暂停；
- 仿真速度固定为零；
- 不挂载 `ScenarioMotionController`；
- 不提供任何可启动物理步进的 UI；
- 场景切换时直接加载目标 XML；
- 保留 `OrbitControls`，仅允许旋转、缩放和有限范围的观察；
- URL 只保存 `scene=demo01` 至 `scene=demo06`，忽略旧 `line` 参数。

## 6. 场景几何整理

当前六个原 Line 1 XML 都存在“静态展示代理 + 同位置动态任务物体”的重复结构。静态展厅中删除动态任务物体及其 `freejoint`，只保留一个可见对象，避免初始重叠和后续物理移动。

逐场执行以下校正：

1. Panda 基座顶面与对应工作台面保持一致，允许独立落地基座，但机器人安装平面不能低于桌面后穿过桌板。
2. Panda 本体、夹爪、工作台、支架和大型设备之间保留可见间隙。
3. 同类物体不共享完全相同的位置、朝向和尺寸空间。
4. 桌上物体底面与承载表面贴合，不悬空、不嵌入。
5. 设备几何不以重叠盒体模拟同一个零件。
6. 相邻 Panda 的静态姿态不互相接触。
7. 相机的默认目标点与场景中心一致，完整容纳三臂或四臂工位。

六个主题保持不变：精密元器件、汽车线束、食品装盒、大型构件、智能药房和岭南果品。

## 7. 删除范围

删除前端中的 Line 2 专属内容：

- `public/scenarios/line2/`；
- `public/assets/line2/`；
- `src/scenarios/line2Catalog.ts` 及对应测试；
- `src/app/LineSelector.tsx`；
- `src/app/RealisticAssetLayer.tsx` 及对应测试或修复副本；
- Line 2 专属端到端测试；
- 仅为播放服务的前端运动控制器和运动目录；
- 其他只被上述模块引用的前端运行时代码。

历史设计文档和项目检查点作为过程记录保留，不进入产品构建，也不在页面显示。

Line 3 原生模拟目录不属于本次页面重构范围，不重新启用，也不在网页中提供入口。

## 8. 测试与验收

### 8.1 自动化契约

先写失败测试，再进行实现。测试至少覆盖：

- 页面只显示六个场景选择按钮；
- 页面不存在 Line 1、Line 2、播放、暂停、复位、任务泳道和任务路径；
- 六个场景都能切换且 URL 只写入 `scene`；
- 视窗处于静态模式，不挂载运动控制器；
- 六个 MJCF 文件全部可编译；
- 六个 XML 中不存在动态任务物体或 `freejoint`；
- Panda 安装高度与场景定义的承载面一致；
- 重复展示代理和同位置任务物体不再同时存在。

### 8.2 几何检查

使用 MuJoCo 在页面采用的固定关节姿态执行 `forward`，检查初始接触集合。机器人之间、机器人与工作台之间不得存在非预期接触。承载物体与桌面之间允许贴面关系，但不得有明显负间隙。

此外，对六个场景分别生成浏览器截图和一张六宫格接触表，由人工检查：

- 机械臂是否竖直安装；
- 基座高度是否合理；
- 物体是否重叠、穿入桌面或悬空；
- 摄像机是否完整容纳场景；
- 页面是否呈现明亮白灰风格；
- 页面是否只剩必要信息。

## 9. 完成定义

满足以下全部条件后才算完成：

1. Line 2 产品代码和资产已删除。
2. 六个场景仍可从同一静态页面访问。
3. 页面没有播放或仿真控制功能。
4. 页面与三维场景均为明亮白灰主色，而非夜间或霓虹风格。
5. 自动化测试、类型检查、构建和 MJCF 编译全部通过。
6. 六场景初始姿态接触检查没有非预期穿模。
7. 六张最终截图和六宫格总览可供用户直接检查。
8. 变更推送到个人仓库 `Shuaijun-LIU/demo` 的部署分支，GitHub Pages 可构建。
