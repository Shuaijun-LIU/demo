# 多机械臂投资人 Web Demo 总体设计

- 状态：已获用户确认
- 日期：2026-08-12
- 实现目录：`/data/private/user2/workspace/7.web-robot/3.our-demo/demo1-6`
- 剧本来源：`../多机械臂Demo场景剧本_投资人展示版_2026-08/`

## 1. 项目目标

构建一个可静态部署、面向投资人展示的一体化 Web 应用，在同一套界面和运行时中承载六个三臂或四臂协作场景：

1. 三臂精密元器件双面检测与设备上料；
2. 四臂汽车低压线束协同布线与质检；
3. 三臂食品多规格装盒、封装与质检；
4. 四臂大型构件定位、工具作业与质量复核；
5. 四臂智能药房随机处方配药与核验；
6. 三臂岭南果品分选、去核与包装。

每个场景都必须展示清楚的开始状态、强耦合协作或在固定路演节拍下不可替代的多臂并行价值、异常闭环和可核对的完成结果。应用部署到纯静态 HTTP 服务后，打开网址即可运行，不依赖后端业务服务、API Key、训练环境或实时网络资源；不承诺通过 `file://` 双击运行。

## 2. 已确认的核心决策

- 采用方案 A：稳定的确定性动作编排为主，关键接触环节选择性使用 MuJoCo。
- 六个场景统一使用 Franka Panda 作为主视觉与运动学模板。
- 使用“共享运行时 + 六个独立场景模块”，不维护六套重复应用。
- 默认中文界面，面向桌面 Chrome 和 1920×1080 路演屏幕。
- 默认演示不调用 LLM、VLA 或云端服务；未来能力通过适配器接入。
- 任务推进采用事件驱动状态机，不把剧本时间点直接实现成脆弱的固定计时动画。
- 所有引用模型和库均保留许可证与署名；不复制缺少明确许可证的示例仓库代码。
- 首个工程基线固定使用 `mujoco-react` 8.2.1，并提交依赖锁文件；升级依赖必须经过六场景回归测试。

## 3. 首版不纳入的范围

- 不宣称达到真实产线的精度、节拍、良率、负载、食品认证或医疗合规。
- 不在首版实现真实柔性体有限元、线缆张力控制器或工业工具反力控制。
- 不在首版接入真实机械臂、PLC、相机或安全控制器。
- 不要求移动端完整操作体验；移动端只保证能打开说明页。
- 不把在线生成式模型作为六个 Demo 能否运行的前置条件。

这些边界不会削弱展示目标：首版交付的是稳定、可验证、可扩展的多臂数字化场景原型。

## 4. 用户旅程

所有场景共享同一条操作流程：

1. **选择场景**：首页显示六张场景卡、臂数、行业、展示定位和当前状态。
2. **进入工位**：加载 Franka、工装、物料、相机和该场景任务清单。
3. **检查初态**：界面列出物料、目标位、安全区和异常注入项，全部通过后允许启动。
4. **启动演示**：一键执行默认确定性任务；支持暂停、继续、1×/2×倍速和复位。
5. **事件推进**：任务图根据抓稳、到位、共享区空闲、检测返回等谓词推进。
6. **异常闭环**：每个场景包含一个可解释、可重复的预设异常及恢复动作。
7. **结果确认**：结果面板同时展示实体状态、对象 ID、订单统计和成功判据。
8. **重新演示或切换**：可用相同种子重新执行任务，也可返回场景矩阵；首版不实现任意时间点的视频式回放。

自动讲解模式会同步切换镜头、突出当前机械臂并显示一句投资人讲解词。高级调试信息默认折叠，避免主界面像开发工具。

## 5. 界面设计

桌面端采用 16:9 深色工业控制台风格：

- 左侧约 72% 为 3D 主舞台；
- 右侧约 28% 为任务、当前阶段、对象统计和异常状态；
- 底部为三条或四条机械臂泳道，显示等待、运动、持物、检测、互锁和恢复；
- 顶部提供场景切换、自动演示、倍速、暂停和复位；
- 绿色表示通过，琥珀色表示进行或等待，红色只表示真实异常或阻塞；
- Arm 1–4 使用稳定的角色色和编号，但 Franka 本体保持统一的工业材质；
- 关键动作采用局部高亮、腕部相机画中画或短暂特写，不频繁切镜头。

首页按“首选落地、技术旗舰、快速商业化、工业旗舰、行业扩展、区域特色”组织六张卡片，避免把六个原型包装成六个已经量产的产品。

### 6.1 AppShell

负责路由、场景选择、加载状态、全局错误边界和展示模式。它不包含任何具体工艺逻辑。

### 6.2 ScenarioManifest

每个场景通过配置声明：

- 场景编号、标题、行业和投资人定位；
- 机械臂数量、基座姿态、角色名称和末端工具；
- 工装、物料、初态、相机和灯光；
- 任务图、异常种子和成功判据；
- 自动讲解词和推荐镜头；
- 是否启用选择性 MuJoCo 接触步骤。

场景模块可以替换资产和任务图，不需要修改应用外壳。

### 6.3 TaskRuntime

TaskRuntime 是六场景共享的核心。每个任务节点包含进入条件、动作、完成谓词、超时策略和恢复边。运行时只在谓词满足后推进，并把每个状态变化写入 TraceRecorder。

### 6.4 Robotics

RobotAdapter 定义统一接口：复位、移动到姿态、沿路径运动、开合夹爪、绑定或释放对象、切换工具、查询状态。FrankaAdapter 是首个实现。未来替换 xArm、UR 或真实硬件时，运行时接口尽量保持稳定，但场景 manifest、可达位姿、轨迹和安全参数允许按机型适配。

### 6.5 Simulation

KinematicScene 负责绝大多数稳定、可重复的演出动作。SelectiveMujocoBridge 只处理值得物理验证的短片段，如夹爪闭合接触、放置后稳定和简化插入。SimulationStateBridge 负责两种模拟模式之间的原子状态交接。

ObjectCustody 将“逻辑保管者”和“物理附件集合”分开：状态支持 `free`、`exclusive(arm)`、`handoff(armA, armB)` 和 `multiAnchor(composite, anchors[])`。双臂共同夹持只允许发生在 Handoff 节点内；线束等复合对象由独立控制点记录附件，只有 manifest 明确声明的强协作节点可以进入 multi-anchor 状态。Handoff 在接收臂确认后收敛为新的独占保管状态，multi-anchor 在夹具接管后收敛为 fixture custody。

## 7. 数据流

1. 用户选择场景，ScenarioRegistry 返回对应 manifest。
2. SceneViewport 根据 manifest 创建工位和 Franka 实例。
3. TaskRuntime 复位对象、谓词、锁和随机种子。
4. 用户启动后，TaskGraph 调度各臂的轨迹或工具动作。
5. 每帧机器人层更新关节、末端和持物状态。
6. PredicateEvaluator 读取对象、区域、检测和工具状态。
7. 条件满足则进入下一节点；条件超时统一进入 `BLOCKED_PAUSED`。自动演示模式立即选择节点声明的恢复边，手动模式等待用户选择“自动恢复”或“复位”。
8. TraceRecorder 将事件提供给 UI、结果面板和相同种子的确定性重新执行。
9. 所有终态谓词通过后生成结构化验收结果。

UI 不维护第二份业务状态；任务面板、对象统计和 3D 场景都读取同一个运行时快照，避免画面与计数不一致。

## 8. Franka Panda 多实例方案

- 模型来源为本地 MuJoCo Menagerie Franka Panda，许可证为 Apache-2.0。
- 构建阶段为每个实例生成独立前缀，例如 `arm1/joint1`、`arm2/joint1`。
- body、joint、geom、site、actuator、sensor、tendon、equality、keyframe、contact exclude 和 default class 全部命名空间化；共享 mesh/material 使用内容哈希命名并保持只读。
- 每个实例通过 manifest 指定基座位置、朝向、初始关节和角色色。
- 视觉网格复用同一缓存；进入物理片段时由 SimulationStateBridge 原子更新 `geom_contype`、`geom_conaffinity` 与碰撞组，退出后恢复快照。
- 平行夹爪为默认末端；软夹、检测探头和工具头由 ToolAdapter 以可替换附件表示。
- 轨迹以关节关键帧和末端路径两种形式保存；运行时统一转换为可插值动作。
- 场景逻辑不得依赖 Franka 的固定关节索引，只依赖 RobotAdapter 和语义化 site 名称。
- 构建测试必须证明四臂组合 MJCF 可编译、所有全局名称唯一、四套控制输入互不串扰。

## 9. 任务协调语义

共享运行时提供以下原语：

- **Predicate**：对象已抓稳、目标位为空、工具已到位、检测已返回、人员区安全等。
- **ZoneLock**：共享区互斥访问，进入前申请，完全退出后释放。
- **Barrier**：两条或多条臂达到指定姿态后同时进入下一阶段。
- **Handoff**：发送臂保持，接收臂闭合并确认，随后发送臂释放。
- **HoldWhile**：一条臂在另一条臂完成工具或检测动作期间持续保持。
- **ScriptedBusinessFault**：按固定种子注入恰好一次观众可见的工艺或订单异常。
- **InfrastructureFault**：模型、物理或渲染故障，只进入技术日志和恢复机制，不计入业务异常次数；默认验收种子若出现此类故障则测试失败。
- **Recover**：退回安全姿态、重新操作、旁路分流或补作业。
- **Reset**：从任意中间状态恢复到统一初态，且可重复调用。

唯一超时语义为 `RUNNING → BLOCKED_PAUSED → RECOVERING | RESETTING`。节点超时不会静默跳过；界面突出阻塞谓词。自动演示在同一渲染帧选择预声明恢复边，手动模式保持暂停并等待用户操作。默认自动演示只使用已经通过契约测试的恢复路径。

每个 manifest 还必须声明 `coordinationClass`（`strong-coupled` 或 `pipeline-sla`）和 `armNecessityOracle`。契约测试会逐条禁用 Arm 1–N：强耦合场景必须出现不可满足的保持/附件谓词；流水场景必须超过该场景的路演节拍上限。仅有并行动画不算多臂必要性。

## 10. 混合仿真策略

### 10.1 确定性编排

机械臂大范围移动、镜头演出、工具扫描、对象分流和包装流程使用轨迹编排。这保证六个 Demo 在路演机器上可重复运行。

### 10.2 选择性物理

以下动作可使用 MuJoCo 短片段：

- 夹爪接近、接触并夹紧刚性物体；
- 物体放入托盘后的稳定；
- 简化连接器或紧固点的导向插入；
- 夹爪松开后的重力落位；
- 接触失败时触发恢复边。

首版选择性物理范围固定为：Demo 01 的刚性件夹持与托盘落位、Demo 03 的产品入盒落位、Demo 04 的 F1/F2 导向接触、Demo 05 的药盒入汇合盘。Demo 02 的线束和 Demo 06 的可拆果核默认使用确定性约束动画；它们仍通过任务谓词和 ObjectCustody 参与统一验收。

物理片段失败不会破坏整场演示：运行时回到片段入口重试一次，仍失败则切换到已验证的运动学落位并在技术日志中记录 InfrastructureFault。默认验收种子必须在不触发该降级的情况下通过。

### 10.3 SimulationStateBridge 协议

场景运行时只有一个规范化 `ScenarioSnapshot`，包含：任务节点、PRNG 状态、每臂 qpos/qvel/ctrl、对象位姿和速度、ObjectCustody/附件、碰撞掩码、工具状态和模拟时间。

进入物理片段时按以下协议执行：

1. 对当前 ScenarioSnapshot 建立不可变 checkpoint；
2. 将坐标系、关节、对象、附件和碰撞掩码完整复制到 MuJoCo；
3. 执行固定步数的 settle，并验证位置/速度误差；
4. 运行物理节点并验证节点完成谓词；
5. 成功时把结果原子提交为新的 ScenarioSnapshot；
6. 失败时完整回滚 checkpoint，再重试或走确定性降级边。

物理片段之外，ScenarioSnapshot 是唯一真值来源。桥接测试对进入、成功提交、失败回滚和降级后的快照哈希做确定性断言。

### 10.4 线束表示

Demo 02 首版不求解真实线缆动力学。线束使用可变形样条管线：

- 两端和中段由机械臂或夹具控制点约束；
- 路径经过 C1–C3、定位柱和 B1 后更新控制点；
- 界面显示张力区间和夹位状态；
- 线束回弹由短暂的阻尼过渡表达；
- 所有夹位通过谓词后才进入终检。

这足以清楚表达三臂共同控线和四臂协作，同时保持稳定。

## 11. 六个场景定义

### 11.1 Demo 01：精密元器件检测与上料

- 臂1：混料取件和 SKU 初分；
- 臂2：共享交接位接件、翻转和双面检测；
- 臂3：模拟功能测试、A/B 上料和 NG 分流；
- 对象：P1–P5，其中 P3 缺少背面标记；
- 异常闭环：P3 外观检测失败后直接旁路到 NG，不再进入功能测试；
- 强协作画面：一次正式 Handoff，以及三臂分别处理不同批次；
- 终态 oracle：P1→A1、P2→B1、P3→NG、P4→B2、P5→A2；全部机械臂回到各自 safe pose。
- 多臂必要性：`pipeline-sla`，五件闭环上限 90 秒；禁用任一臂后任务图缺失必要工序或超过 90 秒。

该场景是首个端到端实现和共享运行时的参考验收场景。

### 11.2 Demo 02：汽车低压线束布线

- 臂1：插入并保持起始连接器；
- 臂2：夹持中段并随动维持张力；
- 臂3：沿主路径布线并直接插入末端连接器；
- 臂4：依次压紧 C1–C3、处理 B1 分支并终检；
- 异常闭环：C2 首次未完全压紧，臂4检测后补压；
- 强协作画面：臂1、2、3共同控制线束，臂4同时处理夹位；
- 终态 oracle：起始/末端连接器分别锁定 S0/S1，C1–C3 与 B1 均为 `closed=true`，线束采样点到目标曲线 RMS 距离 ≤25 mm，归一化张力处于 [0.25, 0.75]，机械臂全部释放并回到 safe pose。
- 多臂必要性：`strong-coupled`；控线阶段要求 Arm 1–3 的三个 anchor 同时有效，Arm 4 获得 clip zone 锁后才能压夹。

### 11.3 Demo 03：食品多规格装盒

- 臂1：按订单供给 A/B 产品；
- 臂2：选择蓝/黄盒并在装盒期间保持；
- 臂3：装入产品、封签、检测和分流；
- 对象：K1–K5，K3 的包装盒外侧日期标签缺失；
- 异常闭环：K3 在封装后检测失败并进入 NG；
- 强协作画面：臂2持盒，臂3装入，同时臂1准备下一件；
- 终态 oracle：K1(A)→Blue-1、K2(B)→Yellow-1、K3(A, missing-date)→NG、K4(B)→Yellow-2、K5(A)→Blue-2；全部机械臂回到 safe pose。
- 多臂必要性：`pipeline-sla`，五件闭环上限 90 秒；Arm 2 持盒与 Arm 3 装入为强制 Barrier/HoldWhile，禁用 Arm 1 则供料节拍超限。

### 11.4 Demo 04：大型构件定位与工具作业

- 臂1：搬运并持续保持主梁；
- 臂2：定位连接板并维持 T 形姿态；
- 臂3：执行 F1/F2 工具动作和接缝轨迹；
- 臂4：侧后方支撑、同步配合并质量扫描；
- 异常闭环：F2 到位开关首次为失败，臂3补作业，臂4复检；
- 强协作画面：四臂围绕同一装配体持续工作；
- 终态 oracle：连接板相对主梁为 90°±3°，基准点位置误差 ≤15 mm，`F1.installed=true`、`F2.installed=true`、`Seam.scanned=true`，构件由 fixture custody 接管，四臂回到 safe pose。
- 多臂必要性：`strong-coupled`；F1/F2 作业期间 Arm 1、2 的保持谓词和 Arm 4 的支撑谓词必须持续为真，否则 Arm 3 的工具节点不可进入。

工具采用低能量演示头或发光探头，不表现高温、飞溅或真实重载。

### 11.5 Demo 05：智能药房配药

- 臂1：从 A 区为两个订单并行拣选；
- 臂2：从 B/C 区拣选，首次为 RX-02 取到 B3；
- 臂3：汇合、扫码、计数，并把错误 B3 移至退回位；
- 臂2：收到恢复指令后补取正确 B1；
- 臂4：仅在订单 PASS 后包装并送至取药窗口；
- 异常闭环：B3 被识别、隔离并替换为 B1；
- 固定验收种子 `RX-20260812`：RX-01={A1×1,B2×1}，RX-02={A2×1,B1×1,C1×1}；B3 是 RX-02 的错误取件。
- 终态 oracle：两个包装盒分别只含对应处方；B3 位于 return bin；五件正确药盒、一个错误盒、库存余量和出入库事件满足守恒；四臂回到 safe pose。
- 多臂必要性：`pipeline-sla`，两单含纠错闭环上限 90 秒；未 PASS 的订单无法获得 Arm 4 包装区锁，禁用任一拣选/汇合/包装角色均导致节拍或终态违约。

处方从有限安全集合按可显示的随机种子生成，所有药盒明确标注为空盒演示。

### 11.6 Demo 06：岭南果品分选与去核

- 臂1：从浅盘取 G1–G6，旋转检查并完成初分；
- 臂2：对合格果定向并执行低力去核；
- 臂3：复核开口并装入透明成品盘；
- G2 进入待熟区，G4 进入 NG，其余四件完成去核；
- 异常闭环：G5 首次去核复核失败，臂2重新执行短行程，随后通过；G2 待熟和 G4 表面缺陷属于正常品质分类，不计为执行故障；
- 强协作画面：三臂同时处理不同果品；
- 终态 oracle：G1/G3/G5/G6→四格成品盘且 `pitRemoved=true`，四枚果核→pit bin，G2→unripe bin，G4→NG；三臂回到 safe pose。
- 多臂必要性：`pipeline-sla`，六件含复作业闭环上限 100 秒；禁用任一分选、去核或复核角色均超过上限。

果品、果核和去核机构使用可复位模型，并在界面明确标注“模型物料”。

### 11.7 共享 oracle 契约

每个 ScenarioManifest 必须同时声明 `initialState`、`expectedFinalState`、`inventoryConservation`、`scriptedFaultEvidence`、`safePoseByArm`、`coordinationClass`、`armNecessityOracle` 和 `maxDemoDurationSec`。结果面板和自动测试读取同一个 oracle，不允许在 UI 中另写期望数字。

距离和角度容差均以演示模型坐标为准；实现计划会把上述 oracle 固化为类型化数据和场景契约测试。safe pose 必须满足关节限位、与其他臂/工装无碰撞，并在 manifest 中给出具体关节值。

## 12. 错误处理与恢复

- **模型加载失败**：显示具体资产和重试按钮，不进入半加载场景。
- **WebGL/WASM 不可用**：显示明确的兼容性说明、受支持浏览器和修复建议，不进入不完整场景。
- **任务谓词超时**：进入 `BLOCKED_PAUSED`，突出未满足条件；自动演示选择声明的恢复边，手动模式等待操作。
- **共享区死锁**：ZoneLockManager 按全局顺序授锁；测试中禁止循环等待。
- **对象保管或附件冲突**：开发模式抛出错误，演示模式进入 `BLOCKED_PAUSED` 并回滚到节点 checkpoint。
- **物理片段不收敛**：记录 InfrastructureFault，原子回滚后重试一次；默认验收种子若仍需降级则判测试失败。
- **用户中途切换场景**：取消当前任务、释放资源后加载新场景。
- **复位**：停止所有轨迹、清理锁和对象绑定、恢复同一随机种子的初态。

## 13. 测试策略

### 13.1 单元测试

使用 Vitest 覆盖：

- TaskGraph 的正常、业务异常、基础设施异常和恢复路径；
- ZoneLock、Barrier、Handoff 和 multi-anchor；
- 谓词求值与 `BLOCKED_PAUSED` 超时语义；
- ObjectCustody、库存守恒和逐对象 oracle；
- SimulationStateBridge 的进入、提交、回滚、降级和快照哈希；
- TrajectoryPlayer、ToolAdapter、CameraDirector 和 FaultInjector；
- TraceRecorder 与相同种子的确定性重新执行；
- manifest 校验、Franka 可达性/关节限位/碰撞和结果统计；
- 任意任务节点 reset 的幂等性。

### 13.2 场景契约测试

每个场景必须自动验证：

- 声明的臂数和实际实例一致；
- `armNecessityOracle` 对每条臂的禁用反事实均成立；
- ScriptedBusinessFault 恰好发生一次、证据可见并进入正确恢复边；
- 默认种子不出现 InfrastructureFault；
- 逐对象终态、库存守恒、订单统计、安全终姿和成功谓词与共享 oracle 一致；
- 强耦合或流水节拍窗口满足 manifest 声明。

### 13.3 浏览器端测试

使用 Playwright 或等价浏览器测试覆盖：

- 六个场景均可从首页进入；
- 自动演示可启动、暂停、继续、1×/2×运行和从任意中间节点复位；
- 初态检查、模型加载失败和 WebGL/WASM 不可用状态可被测试触发；
- 场景连续切换不遗留运行状态；
- 默认种子可完整跑到成功；
- 自动讲解、关键镜头和腕部画中画在声明节点出现；
- 关键阶段截图用于视觉回归；
- 根路径和子路径静态 HTTP 部署均无 404、跨域、WASM MIME 或资源路径错误；
- 构建产物断网运行时没有外部请求，第三方许可证随产物发布。

### 13.4 性能门槛

首次基线测试把 CPU、GPU、内存、浏览器版本和屏幕分辨率写入 `project/benchmark_env.md`。在该目标机上：

- 四臂场景连续运行 120 秒，FPS 中位数 ≥45、5th percentile ≥30；
- 场景首次加载显示进度，缓存后的场景切换 ≤2.5 秒；
- 3D 资产按场景懒加载，离开场景后释放非共享资源；
- 六场景连续循环三次后，JS heap 相对首轮稳定值增长 ≤100 MB，且无任务漂移或统计残留。

### 13.5 静态部署契约

- “静态部署”指通过 HTTP(S) 托管构建产物，不支持 `file://`；
- 同一构建必须支持站点根路径和可配置子路径；
- 所有模型、WASM、字体、图标和场景资源本地化，断开外网后仍可完整运行；
- 服务器必须以正确 MIME 提供 WASM。首版关闭 WASM 线程，因此不要求 COOP/COEP；若未来启用线程，必须新增对应响应头测试；
- 使用 hash 路由或等价静态友好路由，刷新场景深链不会 404。

### 13.6 需求追踪矩阵

实现计划必须维护“需求/组件 → 单元测试 → 场景契约测试 → E2E/性能测试”的映射。TaskRuntime、ObjectCustody、SimulationStateBridge、Franka 多实例、工具/相机、播放控制、错误边界、静态资源和许可证均不得只靠人工验收。
